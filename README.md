# MarbleGame

YouTube 縦型ライブ向けの 2D マーブルゲームです。PixiJSで描画し、Rapier 2Dで赤・青のマーブルを動かします。上段で効果IDを取得 → 下段へワープ → 倍率枠なら値を更新して下段を再抽選 → 出撃枠なら結果をログに出して削除、まで実装しています。効果の本処理・戦闘・YouTube連携は未実装です。

上段は平坦な効果穴と装置の両端を往復する針型障害物2個、下段は板のない結果センサー帯と下から上へ流れる千鳥配置のピンです。可動障害物も実際に球と衝突します。1080×1920・3:4:3の画面構成と赤青独立の抽選ループは維持しています。

## 起動

```powershell
npm install
npm run dev
```

開発サーバーを起動したまま、PC ブラウザまたは OBS のブラウザソースで `http://localhost:5173/` を開いてください。OBS のブラウザソースは幅 `1080`、高さ `1920` を指定できます。GitHub のリポジトリ URL はソースコードの保存先であり、ゲーム画面の URL ではありません。

```powershell
npm run build
npm run preview
```

`preview` はビルド済みの画面を `http://localhost:4173/` で確認します。

ポートが利用できない場合は `npm run dev -- --port 5180` のように変更し、ターミナルに表示されたURLを開いてください。

## 画面とファイル構成

内部座標は1080×1920。配信情報576px、戦闘768px、マーブル576pxの3:4:3です。マーブルは左が赤、右が青で各540×576。小さいウィンドウでは9:16を保って全体を縮小します。

- `src/config/stage.ts`：画面比率、チーム色、上下の装置、開始地点、ピン、効果枠・結果枠の設定と型。
- `src/config/physics.ts`：物理係数、発射条件、生成頻度・上限、固定更新間隔、抽選の上限。
- `src/marble/layout.ts`：設定から寸法・位置を算出する純粋な処理。PixiJSを含まない保存可能なデータを返します。
- `src/marble/physics.ts`：WASM初期化、装置・球・センサーのコライダー生成、衝突と位置の計算、削除。赤青で別のワールドを持ちます。
- `src/marble/obstacles.ts`：山の往復運動、ピン列の生成・上昇・破棄。キネマティック剛体と描画用の共通形状・位置を管理します。
- `src/marble/simulation.ts`：固定刻みの進行、球の状態、効果取得・倍率・出撃、生成と回収。`applySlot` は物理APIに依存しないルール処理です。
- `src/marble/render.ts`：共通形状と補間した球位置をPixiJSで描画。赤青で同じ処理を利用します。
- `src/game.ts`：上部・中央の仮表示と、共通装置を左右に配置する画面構成。
- `src/screen.ts`：ウィンドウサイズへのフィット。
- `src/main.ts`：非同期初期化後の起動、Pixi ticker、リサイズ、非表示タブの停止、HMR時の破棄。
- `tests/layout.test.mjs` / `tests/physics.test.mjs`：配置と実際のRapier WASMを用いた衝突・抽選ループの検証（`npm test`）。

## コンパクトな配置とUI

装置は幅532px、左右余白4px、赤青間の隙間8px（変更前40px）。上段はy=4・高さ200px、下段はy=208・高さ368pxで、段間4px、下端余白0pxです。外壁5pxは残します。通常画面の見出し・説明文を省き、陣営は色、生成地点は実心円、ワープ先は輪、効果は色とA〜D、倍率は数値、出撃は上向き矢印で示します。設定内のタイトル・説明ラベルとデバッグ画面は開発用に残しています。

## 設定を変更する場所

`src/config/stage.ts` の `marbleConfig` を編集してください。赤・青の両方に反映されます。開発サーバー起動中は保存するとViteがページを更新します。本番用は `npm run build` で再生成してください。

| 設定 | 調整内容 |
| --- | --- |
| `upper` / `lower` の `x, y, width, height` | 各装置の位置・サイズ（各陣営の左上が原点） |
| `wallThickness` | 外壁の厚み |
| `start.x, start.y` | 上段の生成地点、下段のワープ先兼再抽選開始地点（装置内のローカル座標） |
| `start.radius` | 開始地点マーカーの見た目の半径。実際の球半径は `physics.ts` の `marble.radius` |
| `row.inset, row.gap` | 壁の内側から枠列までの余白、枠同士の間隔 |
| `row.height, row.openingWidth, row.funnelHeight` | 枠の高さ、入口の開口幅、傾斜の高さ（flat時は0として扱う） |
| `row.entrance` | `open` は板・仕切り・隙間の蓋を持たない全幅センサー帯。その他は `flat`（平坦）、`crater`（逆勾配）、`funnel`（漏斗）。初期値は上段flat・下段open |
| `row.slots` | 枠の個数・左からの順序・ID・ラベル・色・意味 |
| 各slotの `width, height, openingWidth` | 個別の寸法上書き。幅を省略した枠は残り幅を等分 |
| `lower.pins.radius, spacingX, spacingY` | ピンの半径・横間隔・縦間隔 |
| `lower.pins.centerX, firstY, rowCounts` | ピン列の中心、初期配置の先頭の高さ、各行の個数。生成は先頭2行の横配置を交互に繰り返す |
| `lower.pins.positions` | 任意の `{ x, y }` 配列。初期配置を置換し、先頭2行を生成パターンにも利用 |
| `lower.pins.spawnY, despawnY` | 生成位置はnullなら下端から自動計算（初期357px）、数値なら固定の装置内座標。消去境界54px。中心が消去境界へ到達したら削除 |
| `lower.pins.spawnBottomInset` | 1px。spawnYがnullのとき、床の内側からピン外周までの余白。高さ・壁厚・半径変更にも追従 |
| `upper.mountains` | 山のID・中心 `x, y`・`width, height, topWidth`。`topWidth: 0` で三角形、正の値で台形 |

例えば `upper.row.openingWidth: 54 → 24` で上段の入口が狭くなり、`lower.pins.radius: 5 → 8` でピンが大きくなります。`rowCounts: [3, 4]` なら2行7本になります。初期設定は9行49本で下段を広く使います。枠は常に装置下端に揃います。枠を追加する場合は `slots` に一意なIDを追加してください。個別幅の合計・隙間・余白が装置幅に収まり、開口幅が枠幅以下になるように調整します。装置やピンを動かす場合は、各陣営の540×576の領域内に収めてください（自動縮小・衝突回避はしません）。

`open` では `openingWidth` と `funnelHeight` は使わず、枠全幅を判定領域にします。下段は `inset: 0, gap: 0` と幅の等分で床全体を覆います。隙間や固定幅を指定すると判定のない部分ができるため、連続した結果帯を維持してください。板を持つ入口形式に戻す場合は、ピンの生成位置と初期配置も結果枠より上に戻す必要があります。

`action` を抽選ロジックが読み取ります。上段の `effect` は `effectId`、下段の `multiplier` は `factor` を持ち、いずれも `target: 'lower-start'`。下段の `deploy` は `target: 'battle'` ですが、この段階ではログ出力と削除を行います。色やラベルから動作を推測しません。同じ倍率の枠でも配置IDは別にします。効果A〜Dは仮の識別子で、具体的な効果処理は未定です。新しい効果枠や倍率枠は `row.slots` のデータ追加で対応できます。

### 物理と抽選の調整

`src/config/physics.ts` の `physicsConfig` を編集し、ページをリロードします（開発中はViteが自動更新）。実行中の設定書き換えUIや設定保存基盤はありません。設定は起動時にコピーし、両陣営に同じ値を適用します。

| 設定 | 初期値・用途 |
| --- | --- |
| `marble.radius` | 7px。描画と球コライダーの両方に適用 |
| `gravity.x, y` | 0, 700 px/s²。画面の下向きが正 |
| `marble.restitution, friction` | 0.65, 0.08。球同士の衝突にも適用 |
| `materials.wall / pin / funnel` | 外壁・ピン・入口それぞれの反発と摩擦。接触する2物体の係数の平均を使用 |
| `materials.mountain` | 山の反発0.7・摩擦0.04 |
| `marble.density` | 密度1。質量は半径と密度から算出 |
| `marble.linearDamping, angularDamping` | 0.08, 0.1。速度・回転の減衰 |
| `marble.maxSpeed, ccd` | 900px/s, true。全方向の速度上限と、固体への高速衝突検出 |
| `marble.maxFallSpeed` | 160px/s。下向きの速度だけを制限。正の有限値。生成・ワープ時と物理更新前後に適用 |
| `launch.upper` | 260〜460px/s、−65〜20°からランダムに生成 |
| `launch.lower` | 170〜300px/s、20〜160°。効果取得後も倍率再抽選後も新たに発射 |
| `spawn.interval, batchSize` | 1.4秒ごとに1個の生成要求。複数個のバッチは生成地点が空くたびに順次生成 |
| `spawn.maxPerTeam` | 各陣営24個。ワープ待機中の球も含む |
| `spawn.clearance` | 球の直径に加えて1pxの間隔を確保してから生成・再発射 |
| `spawn.automatic` | falseで自動生成を停止。デバッグ画面の手動生成は可能 |
| `simulation.fixedTimeStep` | 1/120秒。描画フレーム間の経過時間を貯め、一定刻みで更新 |
| `simulation.maxSubsteps, maxFrameDelta` | 1フレーム最大12回、経過時間最大0.1秒。余剰時間は捨て、長時間停止後の更新集中を防ぐ |
| `simulation.solverIterations, maxCcdSubsteps` | 8, 4。接触解決とCCDの精度・負荷 |
| `simulation.pixelsPerMeter` | 100。物理内部だけメートルに変換。通常の調整はpxのままで可能 |
| `rules.initialValue, maxValue` | 初期値1、倍率適用後の値上限1,000,000 |
| `rules.maxRerolls, maxLifetime` | 最大12回の再抽選、最大90秒（シミュレーション時間）。超過した球は理由付きで回収し、出撃扱いにはしない |
| `debug.showColliders, logTransitions` | 当たり判定表示、効果・倍率イベントのログ出力。通常はfalse |

角度は右向きが0°、下向きが90°です。例えば球を小さくするなら `marble.radius: 7 → 6`、落下をゆっくりにするなら `marble.maxFallSpeed: 160 → 120`、速くするなら `160 → 220`、出撃頻度を変えるなら `spawn.interval` や `stage.ts` の出口配置・倍率を変更します。これらに処理コードの変更は必要ありません。

重力700px/s²、横移動、上向きの反発、障害物の速度や時計は変更していません。自由落下の実測では、0.6秒で従来相当124.2pxに対して78.9pxになりました。固定ステップ内では重力や衝突で一時的に上限を超えますが、ステップ終了時に制限します。`maxSpeed` は別途、全方向の安全上限として働きます。

### 可動障害物の調整

形状・配置・流れる範囲は `stage.ts`、動かし方は `physics.ts` の `obstacles` にまとめています。

| 設定 | 初期値・用途 |
| --- | --- |
| `obstacles.mountains.enabled` | true。falseで山を非表示・非生成 |
| `obstacles.mountains.motions[].id` | `stage.ts` の山のIDと対応。各IDに1つの動きを設定 |
| `motions[].amplitude` | 中心から左右235pxの振幅。針全体が壁の内側に収まる |
| `motions[].period` | 1往復3.6秒。小さくすると速い。正弦波で滑らかに折り返す |
| `motions[].phase` | 0.75と0.25周期で逆位相。初期位置・移動方向を変更 |
| `obstacles.pinFlow.enabled` | true。falseで初期ピン配置を固定ピンとして表示 |
| `obstacles.pinFlow.speed` | 上方向22px/s |
| `obstacles.pinFlow.spawnInterval` | nullなら `spacingY / speed` 秒（初期約1.45秒）。数値指定なら独立した生成間隔 |
| `obstacles.pinFlow.maxPins` | 各陣営の可動ピン上限64個。マーブルの上限とは別 |

例えば針の幅を変えるなら `upper.mountains[0].width: 18 → 20`、ピンの流れを速くするなら `pinFlow.speed: 22 → 32` を変更します。針の幅や振幅を変える際は、壁に当たらない可動範囲に調整してください。`spawnInterval: null` では速度を変えても行間隔を維持します。間隔を数値指定した場合の縦間隔は `speed × spawnInterval` です。

山は[Rapierの位置制御キネマティック剛体](https://rapier.rs/docs/user_guides/javascript/rigid_bodies/#position)として、固定ステップごとに次の位置を指定します。ピンも同じ方法で動かすため、接触中の球へ速度が伝わります。描画だけで動かしたり、マーブルを上へ移動させたりはしません。描画は直前と現在の物理位置を補間します。

ピンは初期のA/B交互9列から開始し、その後も交互に下端から列単位で追加します。生成場所にマーブルや別のピンがある場合は、そのピンの追加を見送ります。上端では剛体とコライダーを削除し、次の描画更新で対応するGraphicsも破棄します。生成要求の無限蓄積はありません。デバッグ画面の「障害物・追加・削除」カウンターで確認できます。

山の可動範囲が壁・生成地点・入口へ重なる設定や、ピンの生成／消去境界がワープ先・固体の出口・床を妨げる設定は起動時に拒否します。下段のopenセンサー帯は非固体なのでピンの配置・通過が可能です。`crater` へ切り替えたときは、縁の高さと山の下端の間隔にも注意してください。形状の大幅な変更後にはデバッグ表示で確認してください。

板を持つ入口は `layout.ts` が生成する斜面・側壁・底の多角形を描画と物理で共有します。枠間の隙間には小さい可視の蓋を置き、球が枠の裏へ抜けるのを防ぎます。openの結果帯にはこれらの固体を生成せず、外壁・床だけ残します。センサーは枠の内側にあり、球が十分に入った段階で到達を判定します。隣接帯に球がまたがる場合は中心のx座標で結果を一つに決めます。開口幅と枠内部は球の直径より広くしてください。通れない半径・開口幅や、センサーを飛び越す更新間隔・最大速度は起動時にエラーになります。CCDは固体用なので、センサーについては固定刻みと移動量の制約も使用しています。

ワープでは古いボディとコライダーを削除し、下段開始地点が空いてから新しい速度・回転ゼロで再作成します。効果ID・現在値は球のゲーム状態に残ります。待機中は描画せず、上段の効果取得は繰り返しません。出撃・回収でもボディとコライダーを削除します。接触は現在のセンサー交差だけを調べ、1球につき1更新1件まで処理するため、イベント履歴や接触キューは蓄積しません。

### 動作確認用の画面

`http://localhost:5180/?debug`（使用ポートに合わせる）を開くと、手動で赤・青を生成するボタン、一時停止、1ステップ実行、当たり判定表示を利用できます。各陣営の球数・生成数・効果取得数・倍率回数・出撃数・回収数と、最後の結果を表示します。通常のURLではデバッグ操作は表示されません。

ブラウザのコンソールには、出撃時に次の形式で出力します。

```text
[marble:deploy] { team: "red", id: 1, value: 4, effectId: "effect-b", rerolls: 2, ... }
```

上限超過や範囲外の球は `[marble:retire]` と理由を出力します。上部・戦闘ゾーンは引き続きプレースホルダーです。背景タブではシミュレーションを停止します。
